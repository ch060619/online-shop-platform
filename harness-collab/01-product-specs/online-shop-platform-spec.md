## 功能背景

本项目用于完成一个前后端分离的电商购物平台实验，覆盖商品浏览、搜索、购物车、下单和订单管理等核心购物流程。后端提供 RESTful API，前端通过 Vue 3 调用接口展示页面和处理交互。

**当前痛点**：
- 缺少可运行的前后端分离电商实验项目。
- 商品、购物车、订单等核心流程缺少统一接口和数据库模型。
- 订单金额和库存校验需要由后端统一控制，避免信任前端传入数据。

**预期收益**：
- 形成一个可启动、可验证、可演示的电商购物平台。
- 支持 SQLite 初始运行，并保留切换 MySQL 的配置能力。
- 通过统一 API 响应、参数校验和异常处理提升项目规范性。

---

## 目标

**主要目标**：
1. 实现商品列表、商品详情、商品搜索、购物车维护、订单提交、订单列表、订单详情和订单取消功能。
2. 后端采用 Spring Boot MVC 分层架构，Controller、Service、Repository、Domain、Config、Exception、Common 包职责清晰。
3. 前端采用 Vue 3 + Vite + Axios + Element Plus，至少包含商品列表页、商品详情页、购物车页、订单确认页、订单列表页、订单详情页。
4. 初始数据库使用 SQLite，提供 MySQL profile 配置。

**成功指标**：
- 核心 API 均以 `/api` 为前缀并返回统一 JSON 结构。
- 下单时库存不足会失败并返回明确错误提示。
- 订单编号由后端生成，订单金额由后端按数据库商品价格和购物车数量计算。
- Maven 测试可执行，核心 Service 和 Controller 有对应测试。

## 用户故事

### 故事 1：商品展示与搜索

**As a** 访客或普通用户  
**I want** 浏览商品列表、查看商品详情，并按名称、分类、价格区间搜索商品  
**So that** 我可以找到想购买的商品

#### 验收标准

- **Given** 数据库中存在商品  
  **When** 用户打开商品列表页  
  **Then** 页面展示商品名称、图片、价格、库存、分类等信息

- **Given** 用户输入搜索条件  
  **When** 用户按名称、分类或价格区间查询  
  **Then** 系统返回符合条件的商品列表

- **Given** 用户点击某个商品  
  **When** 进入商品详情页  
  **Then** 页面展示该商品的完整描述、价格、库存和分类信息

### 故事 2：购物车管理

**As a** 普通用户  
**I want** 将商品加入购物车、修改数量和删除商品  
**So that** 我可以在下单前管理购买清单

#### 验收标准

- **Given** 商品存在且库存充足  
  **When** 用户加入购物车  
  **Then** 系统新增或累加购物车明细

- **Given** 购物车中已有商品  
  **When** 用户修改购买数量  
  **Then** 系统保存新数量并重新计算总价

- **Given** 购物车中已有商品  
  **When** 用户删除该明细  
  **Then** 商品从购物车移除

#### 异常场景

- **Given** 商品库存不足  
  **When** 用户加入购物车或增加数量超过库存  
  **Then** 系统拒绝操作并返回库存不足提示

### 故事 3：提交订单

**As a** 普通用户  
**I want** 根据购物车商品提交订单  
**So that** 我可以完成购买流程

#### 验收标准

- **Given** 购物车中存在有效商品且库存充足  
  **When** 用户提交订单  
  **Then** 系统生成唯一订单编号，保存订单和订单明细，扣减库存并清空已下单购物车明细

- **Given** 前端传入订单确认请求  
  **When** 后端处理订单  
  **Then** 订单金额由后端根据数据库商品价格和购物车数量计算

#### 异常场景

- **Given** 任一购物车商品库存不足  
  **When** 用户提交订单  
  **Then** 系统拒绝下单，不扣减库存，不创建订单，并返回库存不足提示

### 故事 4：订单管理

**As a** 普通用户  
**I want** 查看订单列表、订单详情和取消订单  
**So that** 我可以追踪和管理自己的订单

#### 验收标准

- **Given** 用户已有订单  
  **When** 用户进入订单列表页  
  **Then** 页面展示订单编号、金额、状态和创建时间

- **Given** 用户点击订单  
  **When** 进入订单详情页  
  **Then** 页面展示订单明细商品、成交价、数量和小计金额

- **Given** 订单状态为已创建  
  **When** 用户取消订单  
  **Then** 系统将订单状态改为已取消并回补库存

## 非功能性需求

### 性能要求

- 常规列表查询在实验数据规模下响应时间应小于 500ms。
- 商品列表接口支持按条件过滤，避免前端一次性拉取无关数据。

### 安全要求

- 引入 Apache Shiro 基础配置，接口预留认证扩展点。
- 实验初版使用固定用户上下文，后续可扩展登录校验。
- 所有请求 DTO 进行 Bean Validation 参数校验。
- 数据库访问通过 MyBatis 参数绑定，避免 SQL 注入。

### 兼容性要求

- 后端使用 Java EE 8、Servlet 3.0、Spring Boot 2.2.x、Spring Framework 5.2.x。
- 初始数据库使用 SQLite，提供 MySQL profile 切换配置。
- 前端支持现代 Chromium 浏览器。

### 可用性要求

- 后端统一异常处理，返回包含状态码、提示信息和数据内容的 JSON。
- 拦截器记录请求路径、请求方法、请求参数和访问时间。
- 前端统一 Axios 请求封装，集中处理错误提示。

## 排除范围

本次迭代不包含以下内容：

- 在线支付、退款和物流配送。
- 管理员后台商品维护。
- 真实注册登录、短信验证码和密码找回。
- 多商户、优惠券、评价、收藏、推荐系统。

**后续迭代计划**：
- 增加真实登录认证和角色授权。
- 增加后台商品和订单管理页面。
- 增加支付模拟和订单状态完整流转。
